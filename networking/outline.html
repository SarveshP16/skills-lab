Networking: why is the site down?

Learn how data really gets from one machine to another, layer by layer. Then capture and read the traffic, catch attacks on the wire, lock a network down, and do it all again in the cloud.

This is the plan for the track. The labs run in the same simulated terminal as the Linux track, on a network of Kestrel Cloud machines (and, in Module 5, an AWS account), with a diagram of the network beside the terminal.

How the labs will work

A real terminal

Type ip, dig, curl, tcpdump, nmap, ufw, wg and a small aws CLI on simulated machines. Tasks tick as you go.

A network diagram

See the machines, subnets and links you're working on. Broken links turn green as you fix them, and an OSI view highlights the lab's layer.

Safe to break

Scans, floods and spoofing only ever hit Kestrel's own simulated network, so you can see attacks happen and learn to stop them.
